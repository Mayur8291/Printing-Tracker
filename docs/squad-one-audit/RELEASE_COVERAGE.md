## How to execute the bound assertions

Use the isolated local harness described in `tools/squad/local_db.py`; do not point these fixture tests at hosted databases. A specific JSON test ID runs with:

```sh
SQUAD_TEST_DATABASE=squad_test_transfers PYTHONPATH=tools/squad \
  tools/canto-sync/.venv/bin/python -m unittest \
  test_jobsheet_concurrency.JobsheetConcurrency.test_distinct_tailors_compete_then_reload_respects_remaining_capacity -v
```

For IDs sourced from `tools/canto-sync/tests`, run from that module’s documented test environment; the JSON source path disambiguates it. Standalone hosted harnesses and SDK scripts are **not** ordinary local unit tests and must follow their own controlled-fixture/configuration instructions. This ledger deliberately does not invoke them or authorize provider mutations.

The manifest format is `squad-release-coverage-index/v1`; it intentionally has no passing cutover cases or release decision. The cutover collector must receive separately produced, current, genuine acceptance evidence.
