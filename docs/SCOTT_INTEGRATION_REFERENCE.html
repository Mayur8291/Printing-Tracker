Authentication Every request: Authorization: Bearer <API_KEY> + Content-Type: application/json. Keys are either the shared DASHBOARD_API_KEY or per-client keys generated in the dashboard (Admin Panel → Integrations → API keys — these can be disabled individually; a disabled key returns 401 KEY_DISABLED). This is an M2M key, not a Supabase JWT.

Order status values (used exactly, no mapping): PENDING → PROCESSING → COMPLETE, or terminal CANCELLED / FAILED.

Stock API

GET /api/v1/stock/snapshot Available qty (on-hand − reserved) for one or more SKUs
Query Params
skus     = SKU-COTTON-WHT-M,SKU-COTTON-WHT-L   // required
facility = SCOTT_1DAY_01                        // optional
Response — 200
{
  "snapshot": {
    "SCOTT_1DAY_01:SKU-COTTON-WHT-M": 120,
    "SCOTT_3DAY_01:SKU-COTTON-WHT-M": 200
  }
}
Keys are FACILITY_CODE:SKU_CODE. Errors: 400 MISSING_SKUS, 401 UNAUTHORIZED.
POST /api/v1/stock/reserve Hold stock for an order
Request Body
{
  "order_code":    "P-53011",
  "facility_code": "SCOTT_1DAY_01",
  "items": [
    {
      "sku_code":  "SKU-COTTON-WHT-M",
      "item_code": "P-1-4201-88",
      "quantity":  50
    }
  ]
}
Response — 201
{
  "reservation_id": "rsv_abc123",
  "order_code":     "P-53011",
  "status":         "RESERVED",
  "expires_at":     "2026-07-21T10:00:00Z"
}
If stock is short — 409
{
  "error": "INSUFFICIENT_STOCK",
  "details": [
    {
      "sku_code":  "SKU-COTTON-WHT-M",
      "requested": 50,
      "available": 12
    }
  ]
}
DELETE /api/v1/stock/reserve/:reservation_id Release a hold — idempotent
Query (optional)
reason = "CANCELLED"   // or "ORDER_EDIT"
Response — 200
{
  "reservation_id": "rsv_abc123",
  "status":         "RELEASED",
  "released_at":    "2026-07-20T11:00:00Z"
}
Errors: 404 RESERVATION_NOT_FOUND, 409 ALREADY_FULFILLED.
POST /api/v1/stock/fulfill/:reservation_id Convert hold to permanent deduction (dispatched)
Request Body (optional)
{ "dispatched_at": "2026-07-20T14:00:00Z" }
Response — 200
{
  "reservation_id": "rsv_abc123",
  "status":         "FULFILLED",
  "fulfilled_at":   "2026-07-20T14:00:00Z",
  "stock_deducted": [
    {
      "sku_code": "SKU-COTTON-WHT-M",
      "deducted": 50,
      "remaining": 70
    }
  ]
}
Idempotent for already-fulfilled. Errors: 404 RESERVATION_NOT_FOUND, 409 RESERVATION_RELEASED.
POST /api/v1/stock/adjust Manual +/- correction (damage, returns, count errors)
Request Body
{
  "facility_code": "SCOTT_1DAY_01",
  "reason": "DAMAGE_WRITE_OFF",
  "items": [
    { "sku_code": "SKU-COTTON-WHT-M", "delta": -12 },
    { "sku_code": "SKU-POLY-BLK-S",   "delta": 50 }
  ]
}
Response — 200
{
  "adjustment_id": "adj_def456",
  "applied_at":    "2026-07-20T09:00:00Z",
  "results": [
    {
      "sku_code": "SKU-COTTON-WHT-M",
      "before": 120,
      "after": 108
    }
  ]
}
409 INSUFFICIENT_STOCK if a negative delta would leave on-hand below the reserved quantity.

Request Body
{
  "order_code":    "P-53011",
  "facility_code": "SCOTT_1DAY_01",
  "due_on":        "2026-07-25T00:00:00Z",
  "customer": {
    "code":  "P-104",
    "name":  "Acme Traders",
    "email": "acme@example.com",
    "phone": "9876543210"
  },
  "shipping_address": {
    "name":          "Acme Traders",
    "address_line1": "12 MG Road",
    "city":          "Pune",
    "state":         "MH",
    "country":       "IN",
    "pincode":       "411001"
  },
  "payment": {
    "instrument":       "CASH",
    "cash_on_delivery":  true
  },
  "comment": "Rush order - dispatch by Friday",
  "items": [
    {
      "item_code":  "P-1-4201-88",
      "sku_code":   "SKU-COTTON-WHT-M",
      "quantity":   50,
      "unit_price": 245.50
    }
  ]
}
Response — 201
{
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "status":             "PENDING",
  "created_at":         "2026-07-20T09:00:00Z"
}
If stock is short — 409
{
  "error": "INSUFFICIENT_STOCK",
  "details": [
    {
      "sku_code":  "SKU-COTTON-WHT-M",
      "requested": 50,
      "available": 12
    }
  ]
}
If order_code already open — 409
{
  "error": "ORDER_EXISTS",
  "details": {
    "dashboard_order_id": "ord_abc123",
    "status": "PENDING"
  }
}
Store dashboard_order_id — it is the id for all later calls. Re-using an order_code is allowed after CANCELLED/FAILED. On ORDER_EXISTS, adopt the returned id instead of retrying (covers lost 201 responses).
GET /api/v1/orders/:dashboard_order_id Current status + items (reconciliation / support)
Response — 200
{
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "status":             "PROCESSING",
  "updated_at":         "2026-07-20T12:00:00Z",
  "items": [
    { "sku_code": "SKU-COTTON-WHT-M", "quantity": 30, "dispatched_quantity": 0 }
  ]
}
404 ORDER_NOT_FOUND for unknown ids. Status changes are pushed via the order.status_changed webhook — polling not required.
PATCH /api/v1/orders/:dashboard_order_id Edit items / address / due date before dispatch

Full replace of items / shipping_address / due_on (same shapes as create; omitted fields untouched). The old stock hold is swapped for a new one — shrinking an order never fails because its own held stock is credited during the availability check.

Request Body
{
  "due_on":           "2026-07-27T00:00:00Z",
  "shipping_address": { /* same shape as create */ },
  "items": [
    {
      "item_code":  "P-1-4201-88",
      "sku_code":   "SKU-COTTON-WHT-M",
      "quantity":   30,
      "unit_price": 245.50
    }
  ]
}
Response — 200
{
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "status":             "PENDING",
  "updated_at":         "2026-07-20T10:00:00Z"
}
If already dispatched / terminal — 409
{
  "error": "ORDER_NOT_EDITABLE",
  "details": { "status": "COMPLETE" }
}
Also possible: 409 INSUFFICIENT_STOCK, 404 ORDER_NOT_FOUND.
DELETE /api/v1/orders/:dashboard_order_id Cancel — releases held stock, idempotent
Query (optional)
reason = "CUSTOMER_CANCELLED"
       // or "ORDER_EDIT", "OUT_OF_STOCK"
Response — 200
{
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "status":             "CANCELLED",
  "cancelled_at":       "2026-07-20T11:00:00Z"
}
Cancelling an already-cancelled order returns 200 with the original cancelled_at. 409 ORDER_NOT_EDITABLE when already COMPLETE or FAILED.
POST /api/v1/orders/:dashboard_order_id/status Dashboard-internal: progress fulfillment

How the dashboard side moves an order forward (not part of the Scott-facing spec, same bearer key). Every transition fires the order.status_changed webhook.

Request Body
{
  "status": "PROCESSING",
  // or "COMPLETE" (+ optional "dispatched_at")
  // or "FAILED"
}
Response — 200
{
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "status":             "COMPLETE",
  "updated_at":         "2026-07-20T14:00:00Z",
  "dispatched_at":      "2026-07-20T14:00:00Z"
}
TransitionEffect
PROCESSINGAllowed from PENDING only
COMPLETETerminal — fulfills the reservation (permanent deduction), sets dispatched_at + per-item dispatched_quantity
FAILEDTerminal — releases the stock hold
Errors: 400 INVALID_STATUS, 409 ORDER_NOT_EDITABLE / INVALID_TRANSITION, 404 ORDER_NOT_FOUND. Use DELETE to cancel.

Webhooks (dashboard → Scott backend)

Configured via secrets SCOTT_WEBHOOK_BASE_URL + SCOTT_WEBHOOK_SECRET. Until both are set, events queue in an outbox and deliver on the next API call after configuration. Every request is signed: 

X-Dashboard-Signature: sha256=<hmac-sha256-hex(rawBody, SCOTT_WEBHOOK_SECRET)>
Respond 2xx (e.g. 200 { "received": true }). Anything else — or a timeout — keeps the event queued and it is retried on the next stock/order mutation. Deduplicate on event_id. Verify the signature against the raw request body before trusting the payload.
POST {your_server}/webhooks/orders/status_changed Fired on every order status transition
Payload
{
  "event":              "order.status_changed",
  "event_id":           "evt_pqr678",
  "occurred_at":        "2026-07-20T14:00:00Z",
  "dashboard_order_id": "ord_abc123",
  "order_code":         "P-53011",
  "previous_status":    "PROCESSING",
  "status":             "COMPLETE",
  "dispatched_at":      "2026-07-20T14:00:00Z"
}
dispatched_at is present only when the new status is COMPLETE.
POST {your_server}/webhooks/stock/level_changed Fired whenever available stock changes
Payload
{
  "event":         "stock.level_changed",
  "event_id":      "evt_abc123",
  "occurred_at":   "2026-07-20T14:00:00Z",
  "facility_code": "SCOTT_1DAY_01",
  "trigger":       "RESERVATION",
  "changed_skus": [
    {
      "sku_code":       "SKU-COTTON-WHT-M",
      "previous_stock": 120,
      "current_stock":  119
    }
  ]
}
trigger is one of RESERVATION / RELEASE / FULFILLMENT / ADJUST. Stock values are available quantity (on-hand − reserved).
POST {your_server}/webhooks/stock/low_threshold Fired when available qty drops below a SKU's reorder point
Payload
{
  "event":         "stock.low_threshold",
  "event_id":      "evt_def456",
  "occurred_at":   "2026-07-20T14:00:00Z",
  "facility_code": "SCOTT_1DAY_01",
  "low_stock_items": [
    {
      "sku_code":  "SKU-COTTON-WHT-M",
      "available": 8,
      "threshold": 20
    }
  ]
}
Verifying the signature (Node.js)
const crypto = require("crypto");

function verify(rawBody, signatureHeader, secret) {
  const expected = "sha256=" +
    crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(signatureHeader), Buffer.from(expected));
}
Connectivity test: dashboard admins can send a signed test stock.level_changed (with "test": true) from the header environment popover → Send test webhook. Use it to verify your receiver before real traffic.

Realtime / Websockets

There is no custom websocket server — realtime uses Supabase Realtime (websocket under the hood: wss://<project-ref>.supabase.co/realtime/v1/websocket). Backend integration should prefer the webhooks above; realtime is for logged-in clients that want push updates without polling.

WS Supabase Realtime — postgres_changes Tables published for live subscriptions
TableWhat it drives
scott_orders, scott_order_itemsReady Stock Order tab — app orders appear/update instantly
inventory_facility_stockReserved / Available columns + KPIs refresh on reserve/release/fulfill
internal dashboard tables (orders, chat, goals, …)Rest of the dashboard live sync
Subscribing from a client (requires Supabase login — tables are read-only to clients)
import { createClient } from "@supabase/supabase-js";

const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY);
// sign in first — scott_orders is readable by authenticated users only

supabase
  .channel("orders-live")
  .on("postgres_changes",
    { event: "*", schema: "public", table: "scott_orders" },
    (payload) => console.log("order changed:", payload))
  .subscribe();
All published tables are read-only for clients — mutations only via the REST API above.
